# Issue Tracker: GitHub

Repository: `AyaseMinami/gnbp-image-generator`

Issues and product requirements live in GitHub Issues and are managed with the
`gh` CLI. Feature work should begin with an approved issue.

## Conventions

- Create, read, comment on, label, and close issues with the corresponding
  `gh issue` command.
- Read an issue's body, comments, and labels before acting on it.
- When a skill says to publish to the issue tracker, create a GitHub issue.
- When a skill says to fetch a ticket, read the complete GitHub issue.
- Infer the repository from the checkout's `origin` remote.

## Pull Requests As A Triage Surface

External pull requests are not a request or triage surface. External feature
work should start as an issue and receive scope approval before implementation.
Maintainer and collaborator pull requests continue to use the normal review
workflow.

GitHub issues and pull requests share one number space. Resolve an ambiguous
`#<number>` reference before acting on it.
